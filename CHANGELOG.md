# История изменений MarCat

Все заметные изменения пользовательских версий MarCat собраны в этом файле.

## 0.3.6 — 2026-07-28

База сравнения: 0.3.5.

### Добавлено

- Встроенный Маркот теперь может работать через Claude Code или Codex CLI: выбранный клиент использует существующий вход по подписке, а в настройках виден фактический тип авторизации — подписка, OAuth-токен Claude или отдельно оплачиваемый API-ключ.
- Для Codex добавлена готовая команда подключения MarCat MCP; Claude Code по-прежнему получает проектный `.mcp.json`.
- MCP-агенты могут атомарно фиксировать сразу несколько отправленных писем инфлюенсерам; безопасный повтор не создаёт дубликаты и возвращает проверенный итоговый статус каждого контакта.
- В разделе инфлюенсеров появился фоновый поиск YouTube-каналов по играм-референсам или тематике: с профилями поиска, пересечениями по свежим видео, локальным фит-скорингом без LLM, публичными email, дневной квотой и отдельным списком кандидатов перед добавлением в CRM.

### Изменено

- Подключение MarCat к внешнему Codex / Claude Code теперь явно показано как основной рекомендуемый способ работы и отделено от необязательной интеграции DevHub.
- Коннекторы собраны в компактный список со статусами; поля ключа и бюджета раскрываются только для выбранного сервиса.
- Повторный запуск того же YouTube-поиска переиспользует свежий результат и кэш запросов; кандидаты, видео-доказательства и контакты дедуплицируются по стабильным идентификаторам, а остановленный квотой процесс сам продолжится после следующего дневного сброса.

### Исправлено

- Пересборка MCP-сервера больше не ломает ранее подключённые проекты: старый путь `dist/index.js` остаётся совместимым, а новые подключения используют актуальный `dist/index.cjs`.
- Массовая фиксация переписки больше не выдаёт ложный успех при заблокированной базе: записи выполняются последовательно с повтором временных блокировок, а касание и переход воронки сохраняются одной операцией.

## 0.3.5 — 2026-07-27

База сравнения: 0.3.4.

### Изменено

- Добавлен быстрый поиск по текущему разделу и всей базе с управлением с клавиатуры и `Ctrl+F` в любой раскладке.
- Карточки сроков в «Обзоре» теперь открывают связанные задачи, а строка релиза — редактирование проекта.

## 0.3.4 — 2026-07-24

База сравнения: 0.3.3.

### Добавлено

- Появился проектный раздел «Комментарии» с отдельной вкладкой для каждой подключённой площадки, счётчиками требующих ответа сообщений и сохранением выбранной вкладки и фильтра.
- MarCat собирает отзывы и публичные комментарии из Steam, Google Play, itch.io, Game Jolt, Poki, CrazyGames и Incremental DB; обработка страниц выполняется детерминированными коннекторами без нейросетей.
- Комментарии можно отметить новыми, прочитанными, отвеченными или не требующими ответа, открыть на исходной площадке либо передать Маркоту для анализа и подготовки черновика.
- Кнопка «Добавить площадки» ведёт прямо к отфильтрованному списку коннекторов в «Источниках данных»; подключённые источники проверяются в фоне, пока приложение открыто.
- Подключённые через MCP Claude CLI и Codex CLI могут читать комментарии и обновлять их рабочий статус отдельными инструментами.

### Надёжность

- Состояние ответа синхронизируется с площадкой, изменённый игроком отзыв снова возвращается в очередь, а ошибка проверки видна отдельно и не маскируется под отсутствие комментариев.
- Импорт идемпотентен: повторная проверка обновляет существующий отзыв по внешнему идентификатору и не создаёт дубликаты.

## 0.3.3 — 2026-07-24

База сравнения: 0.3.2.

### Добавлено

- В каждом проекте теперь есть обязательный инсайт «Карточка проекта» — единое каноническое описание игры для человека, Маркота и MCP-агентов.
- Карточа закреплена первой в списке инсайтов, показывает статус заполнения и может быть заполнена вручную или передана Маркоту.
- MCP всегда возвращает эту карточку в каталоге инсайтов и позволяет агенту обновлять её как через `update_insight`, так и через `update_project_card`.

### Надёжность

- Обязательную карточку нельзя удалить, переименовать или создать её дубль; MarCat хранит происхождение последней правки: человек, MCP-агент или Маркот.

## 0.3.2 — 2026-07-24

База сравнения: 0.3.1.

### Добавлено

- Задачу теперь можно сделать повторяемой при создании или позже в карточке: достаточно включить понятный переключатель и задать интервал в днях, неделях, месяцах или годах.
- После выполнения очередного цикла задача автоматически возвращается в «К выполнению», очищает чеклист и получает ближайший следующий срок; повторяемые задачи отмечены отдельным значком в списке и на карточках.
- MCP поддерживает включение, изменение и отключение повторения при создании и редактировании задачи, а после завершения явно сообщает агенту новый срок.

### Надёжность

- Просроченная повторяемая задача переносится сразу на ближайший будущий период и не создаёт новый уже просроченный цикл; календарный расчёт корректно учитывает недели и конец месяца.
- Настройки повторения сохраняются в Markdown-пространстве проекта и проходят через тот же двусторонний обмен, что остальные поля задачи.

## 0.3.1 — 2026-07-23

База сравнения: 0.3.0.

### Добавлено

- В карточке инфлюенсера теперь можно хранить игры, в которые он играет, а в проектной воронке — один или несколько отправленных ему ключей; эти данные участвуют в поиске подходящих авторов и доступны через MCP.
- В настройках появился защищённый ключ GMass, а в разделе «Инфлюенсеры» — мастер «Организовать рассылку» с выбором категорий адресов, шаблона, режима черновика, немедленной или отложенной отправки.
- Перед запуском MarCat показывает точный персонализированный текст для каждого получателя и позволяет исключить отдельные адреса; контакты с запретом на связь, неподходящие категории и дубли исключаются автоматически.
- Очередь GMass автоматически создаёт персональные кампании, синхронизирует отправки, открытия, клики, ответы, отказы и отписки, а подтверждённые отправки и ответы фиксирует в журнале и воронке инфлюенсеров.
- MCP получил полный цикл управления рассылкой: предпросмотр, создание неизменяемого снимка, подтверждение с проверкой числа получателей и хеша, просмотр кампаний, запрос синхронизации и безопасный повтор ошибочных адресов.

### Надёжность и приватность

- GMass API-ключ хранится в системном защищённом хранилище приложения и не передаётся MCP-процессу; MCP только ставит подтверждённую операцию в локальную очередь, которую выполняет desktop-приложение.
- Повторная обработка не создаёт дубликаты для уже успешных получателей, а события отправки и ответа импортируются идемпотентно.

## 0.3.0 — 2026-07-23

### Добавлено

- Подготовлен самодостаточный portable-релиз для внешнего распространения: приложение запускается без установки и не содержит пользовательских проектов, настроек, ключей или локальных баз.
- Чистая установка начинает работу с общим календарём Steam-фестивалей и шоукейсов; в него входят только названия, типы событий и даты проведения или подачи заявки.
- Рядом с файлами релиза находится русскоязычный README с быстрым стартом, пояснением хранения данных и подключением необязательных интеграций.

### Надёжность и приватность

- Релизная проверка отклоняет сборку, если в упакованные ресурсы попали SQLite-базы, файлы секретов, переменные окружения или локальное состояние MarCat.
- Публичный календарь проходит отдельную проверку схемы: проектные связи, заметки, контакты, источники и внутренние статусы в него не допускаются.

## 0.2.1 — 2026-07-23

### Добавлено

- У фестивалей и инфлюенсеров появилось единое поле стоимости участия в USD; оно видно в обеих таблицах, поддерживает сортировку и одинаково показывает бесплатное участие.
- MCP возвращает `costUsd` при запросе каталогов фестивалей и инфлюенсеров и принимает это же поле при создании и обновлении записей.

### Изменено

- Существующие взносы фестивалей и ставки инфлюенсеров сохранены и представлены как одно универсальное значение стоимости; старые имена полей остаются совместимыми во входах MCP.

## 0.2.0 — 2026-07-22

### Добавлено

- Для каждого проекта можно включить открытое Markdown-пространство рядом с исходниками: задачи, инсайты, карточка проекта, кампании, посты и журнал остаются доступны в Obsidian, VS Code и Git без привязки к интерфейсу MarCat.
- В настройках появились выбор и открытие папки, ручное сканирование и экспорт, счётчики состояния, а также понятная обработка конфликтов, некорректных документов и пропавших файлов.
- MarCat создаёт готовые таблицы Obsidian Bases для задач, инсайтов, активности и кампаний, не перезаписывая пользовательские настройки представлений.
- MCP получил инструменты состояния, повторного сканирования, диагностики и просмотра путей Markdown-пространства; изменения из MCP проходят через тот же безопасный двусторонний обмен.

### Изменено

- SQLite остаётся быстрым и надёжным индексом приложения, а включаемый пользователем Markdown-слой хранит переносимую человекочитаемую копию рабочих данных. Проекты без включённого пространства продолжают работать как раньше.
- Экспорт и повторное сканирование оптимизированы для сотен файлов: очередь выгружается полностью, неизменившиеся документы не переписываются, а сверка не выполняет повторные полные выборки для каждой записи.
- Смена папки проекта теперь оставляет старые файлы нетронутыми и создаёт полный набор документов в новом месте, включая пути с пробелами и Unicode.

### Надёжность

- Запись файлов выполняется атомарно с проверками выхода из корня, символических ссылок и коллизий имён; чужой файл с совпавшим именем никогда не перезаписывается.
- Параллельная работа desktop и MCP использует долговечную очередь с межпроцессным захватом; импорт одного документа не подавляет изменения других записей.
- Одновременные правки сохраняют обе версии в `Conflicts`, а внешнее удаление требует явного восстановления или архивации в `Quarantine/Deleted` и никогда молча не удаляет запись SQLite.
- Некорректный YAML, повторяющиеся ID, недопустимые статусы и нарушение правил завершения или зависимостей задач изолируются как диагностируемые проблемы без повреждения базы.
- Перед переносом Salt and Soil создана проверенная резервная копия SQLite; после миграции количества записей, Markdown-файлы, Obsidian Bases и двусторонний обмен проверены автоматически.

## 0.1.8 — 2026-07-22

### Добавлено

- В шапке «Обзора» появилась постоянная компактная панель ключевых показателей проекта: позиция в топ-1000 ожидаемых игр Steam, вишлисты, продажи, отзывы Steam и оценка критиков.
- MarCat самостоятельно проверяет публичный топ ожидаемых игр Steam и показывает позицию проекта; если игра не входит в топ-1000, на её месте остаётся аккуратный прочерк.
- Отзывы Steam обновляются автоматически и показывают общее количество вместе с долей положительных.
- Добавлен коннектор Steamworks Financial API для точных продаж и автоматического продолжения истории вишлистов от последнего импортированного баланса.
- Оценку Metacritic или OpenCritic можно подключить одним кликом из «Обзора», указав ссылку на страницу игры.

### Изменено

- Метрики магазинов обновляются в фоне каждые шесть часов и не требуют повторной ручной загрузки CSV после подключения нужного источника.
- Отсутствующие продажи, отзывы, оценки и позиция в топе всегда отображаются единообразным прочерком, поэтому шапка не меняет структуру при появлении новых данных.

## 0.1.7 — 2026-07-22

### Добавлено

- Внутри каждого проекта появился раздел «Инсайты» для выводов об аудитории, результатах экспериментов и проверенных или опровергнутых гипотезах.
- Инсайты можно создавать и редактировать вручную, через MCP и через предложения встроенного Маркота; у каждой записи сохраняется источник.
- MCP отдаёт агенту компактный каталог заголовков инсайтов в карточке проекта и позволяет отдельно запросить полный текст только нужных записей.
- Маркот учитывает релевантные инсайты при анализе проекта и может создавать новые или уточнять существующие выводы через обычный поток ревью.
- Раздел запоминает выбранную запись, режим просмотра, поиск и видимость списка отдельно для каждого проекта.
- Правый клик по записи или открытому тексту позволяет открыть местоположение указанного в инсайте локального файла.

### Изменено

- Инсайты по умолчанию открываются в предпросмотре; область чтения адаптируется к окну, а длинные заголовки корректно переносятся.
- Список сворачивается компактной иконкой рядом с поиском, освобождая основную область для чтения.
- Кнопка сохранения появляется только в режиме редактирования после изменения записи.
- Внутренние интеграции не отображаются в обычном интерфейсе и настраиваются только в разделе настроек.

## 0.1.6 — 2026-07-21

### Добавлено

- Поиск по задачам внутри проекта: по ключу, названию и описанию.
- Сортировка задач в списке и канбане по ключу, названию, статусу, приоритету, датам создания и обновления, началу и сроку выполнения.
- Вложенное отображение зависимых задач в списке с возможностью сворачивать отдельные ветки.
- Индивидуальная настройка подсветки тегов: любой тег можно оставить нейтральным или выделить выбранным цветом.

### Изменено

- Список задач стал существенно компактнее и помещает больше работы на одном экране; чекбоксы массового выбора больше не занимают отдельную колонку.
- Статусы получили удобную цветовую семантику: нейтральный для очереди, синий для работы, красный для блокировки и зелёный для завершения.
- Канбан получил более компактные карточки и спокойную цветовую маркировку колонок.
- Правая панель задачи переработана в двухколоночный рабочий вид: описание, чеклист и активность отделены от статуса, сроков, тегов и зависимостей, поэтому важные данные требуют меньше прокрутки.

## 0.1.5 — 2026-07-21

### Добавлено

- Детерминированная очередь следующих действий для Codex: она учитывает важность, сроки, текущую работу, прогресс чеклиста и разблокируемые задачи.
- Атомарное завершение задач через MCP: подтверждённые пункты чеклиста закрываются вместе с родительской задачей, а незавершённые возвращаются агенту явно.
- Обязательная сверка Definition of Done в правилах MCP перед отчётом о завершении работы.
- Номер версии и окно «Что нового» с полной историей изменений в настройках.
- Версия в имени portable-файла и копия этого changelog рядом с файлами релиза.

### Изменено

- Карточка проекта и список задач теперь показывают прогресс чеклистов и предлагают сначала дожимать важную почти готовую работу.
